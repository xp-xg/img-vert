Best image formats for print

TIFF — the professional print standard

TIFF (Tagged Image File Format) is the format of choice for professional print work — magazines, books, brochures, large-format printing. It has been the print industry standard for decades because:

  • Lossless compression: No pixel data is ever discarded
  • CMYK colour space support: Professional printers use CMYK (Cyan, Magenta, Yellow, Key/Black) rather than the RGB used by screens. TIFF supports CMYK natively; JPG only supports RGB.
  • High bit depth: TIFF supports 16-bit and 32-bit per channel, preserving fine tonal gradations essential for high-quality print output
  • No generation loss: A TIFF can be opened, edited, and saved thousands of times with no quality loss

When to use TIFF: Submitting files to professional printers, print magazine layouts, large-format banners, product packaging, archiving original high-resolution images.

JPG for consumer print

For everyday photo printing — photo books, standard prints, home printers — high-quality JPG (quality 90–95) is perfectly adequate. Most consumer photo labs accept JPG and the compression artefacts at high quality settings are invisible in print.

The key consideration: JPG only supports RGB. If your printer requires CMYK files, you need TIFF. For home printers and consumer photo labs, JPG is fine.

PNG for print — limited use

PNG can be used for print in some cases — logos, diagrams, illustrations — but it only supports RGB, not CMYK. For professional printing, TIFF is preferred. PNG is more useful for digital graphics that might also be printed occasionally.

Best image formats for web

WebP — the modern web standard

For new web projects in 2026, WebP should be the default choice for all images. It produces files 25–34% smaller than equivalent JPEG quality and 26% smaller than equivalent PNG, while supporting transparency and animation. With 96%+ browser support, there is almost no reason to use JPEG or PNG for new web content.

JPG for web photos

JPG remains appropriate for web photos when WebP is not an option — compatibility with older systems, platforms that don't accept WebP uploads (like some social media), or email attachments.

For web use, target JPG quality 75–85. Higher than 85 adds file size with no visible benefit at typical screen resolutions.

PNG for web graphics

PNG remains the choice for logos, icons, and UI elements that require a transparent background — when WebP lossless is not suitable. PNG is especially important for SVG-like graphics with flat colours and sharp edges, where JPG compression creates visible artefacts.

Resolution: print vs web — a critical difference

Print and web have very different resolution requirements, and this affects how you prepare and export images:

PrintWeb / Screen
Standard resolution300 DPI (dots per inch)72–96 PPI (pixels per inch)
Large format print150–200 DPIN/A
What determines qualityDPI + physical sizePixel dimensions
Typical file sizes10–100+ MB50 KB – 500 KB

A common mistake: designers export high-DPI images for web, resulting in enormous file sizes with no benefit. A 300 DPI image displayed on a screen renders identically to a 96 DPI image of the same pixel dimensions — the DPI setting is meaningless for screen display. What matters for web is pixel dimensions, not DPI.

Conversely, a 72 DPI image printed at A4 will look blurry and pixelated — screens can display it fine, but printers need much more data per physical inch.

Colour space: RGB vs CMYK

This is one of the most important and misunderstood aspects of print vs web image preparation.

  • RGB (Red, Green, Blue) — the colour model used by all screens. JPG, PNG, and WebP all use RGB.
  • CMYK (Cyan, Magenta, Yellow, Black) — the colour model used by professional printing. Ink is mixed from these four base colours. TIFF supports CMYK; most other common formats do not.

If you submit an RGB image to a professional printer, they will convert it to CMYK — and this conversion can shift colours noticeably, especially vibrant blues, bright reds, and vivid greens. For critical print work, convert to CMYK yourself (in Photoshop, Illustrator, or GIMP) so you can preview and correct the colour shift before submitting.

For web images, always use RGB. A CMYK image displayed on screen will often look dull and flat because browsers expect RGB.

Converting between print and web formats

When moving an image from a print workflow to web publishing (or vice versa), format conversion is usually necessary:

Print to web (TIFF → WebP or JPG)

If you have a high-resolution TIFF from a print project and need a web version:

  1. Resize pixel dimensions to web display size (typically 1200px wide maximum)
  2. Convert colour space from CMYK to RGB if needed
  3. Convert to WebP or JPG using img-vert's free TIFF to JPG converter or TIFF to WebP converter

Web to print (JPG/PNG → TIFF)

Web images generally don't make good print sources — they're typically too low resolution. A 1200px wide JPG at 96 DPI printed at A4 (210×297mm) would render at only about 45 DPI — far too blurry for professional print. Always use the original high-resolution source, not the web export, for print work.

Frequently Asked Questions

What image format is best for printing?

TIFF in CMYK colour space for professional printing. High-quality JPG (quality 90–95) for consumer photo printing and home printers.

Is TIFF better than JPG for print?

For professional print, yes. TIFF is lossless, supports CMYK, and handles high bit depths needed for professional output. For casual photo printing, JPG at high quality (90–95) is indistinguishable from TIFF in the final print.

What is the best image format for a website?

WebP for all web images in 2026 — it's 25–34% smaller than JPG and 26% smaller than PNG, with 96%+ browser support. Fall back to JPG for photos and PNG for graphics with transparency if WebP isn't supported by your platform.

What DPI should web images be?

DPI doesn't matter for web images — browsers ignore it. What matters is pixel dimensions. For web, focus on pixel width (typically 800–1920px depending on use) rather than DPI.
